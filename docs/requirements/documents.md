# 문서 생성·편집·승인

> 상태: 예정 ([changes/001-mvp.md](../changes/001-mvp.md))

## 목적

[문서 세트](../0-PRODUCT.md#생성하는-문서-세트)를 정해진 순서로 하나씩 만들고, 사용자가 다듬어 승인한 문서를 다음 문서의 입력으로 쓴다.

## 생성 순서

| 순서 | 문서 (경로) | 생성 조건 |
| --- | --- | --- |
| 1 | `0-PRODUCT.md` | 인터뷰가 `approved` 또는 `skipped` |
| 2 | `1-SYSTEM-ARCHITECTURE.md` | `0-PRODUCT.md` 승인 |
| 3 | `3-DATABASE.md` | `1-SYSTEM-ARCHITECTURE.md` 승인 |
| 4 | `4-USERFLOW.md` | `3-DATABASE.md` 승인 |
| 5 | `requirements/<기능>.md` (기능마다) | `4-USERFLOW.md` 승인. 요구사항 문서끼리는 순서 없음 |
| 6 | `screens/<화면>.html` (화면마다) | 모든 `requirements/` 문서 승인. 화면끼리는 순서 없음. 화면이 없으면 건너뜀 |
| 7 | `changes/001-mvp.md` | 모든 `requirements/` 문서와 `screens/` 화면 승인 |

`2-DESIGN.md`와 `AGENTS.md`는 생성하지 않는다 ([0-PRODUCT.md](../0-PRODUCT.md#생성하는-문서-세트)). 화면 정의서의 목록 확정·편집·주석 수정은 [screens.md](screens.md)에서 정한다. 이 문서의 나머지 규칙(되돌리기, 승인, 동시 실행)은 화면 정의서에도 같다.

## 동작

- **생성**: 단계마다 에이전트(`claude` | `codex`)를 골라 생성한다. 결과는 스트리밍으로 보이고, 끝나면 `draft`로 저장된다.
- **직접 편집**: 마크다운 편집기 + 미리보기로 수정하고 저장한다.
- **피드백 재생성**: 피드백을 입력하면 현재 본문(직접 수정 포함)과 피드백을 에이전트에 넘겨 **문서 전체**를 다시 받아 교체한다.
- **되돌리기**: 재생성 직전 본문으로 복구한다. 1회분만 보관한다.
- **승인**: `approved`가 되고 다음 단계의 생성이 가능해진다.

## 기능 목록 확정

`0-PRODUCT.md`를 승인할 때 본문의 `requirements/<기능>.md` 링크를 모아 요구사항 문서 목록을 만든다.

- 승인 화면에 뽑아낸 목록을 보여 준다. 목록을 바꾸려면 `0-PRODUCT.md` 본문을 고친다.
- 기능 이름(`<기능>`)은 영문 소문자·숫자·`-`만 쓴다.
- `agents`는 쓸 수 없다. 대소문자를 구분하지 않는 파일 시스템(macOS 기본)에서 에이전트 지시 파일 `AGENTS.md`로 읽힌다.
- 링크가 하나도 없거나 위 규칙에 어긋나면 승인할 수 없고, 이유를 표시한다.

## 생성 입력

모든 문서: 문서별 고정 프롬프트 + 문서 규칙(`AGENTS.md`) + 아이디어 + 승인된 인터뷰 요약(있으면) + 디자인 문서(있으면) + 승인된 앞 문서 전부.

- `requirements/<기능>.md`: 고정 문서 4개까지만 넣고 다른 요구사항 문서는 넣지 않는다. 대상 기능 이름을 함께 넣는다.
- `screens/<화면>.html`: [screens.md](screens.md#생성).
- `changes/001-mvp.md`: 승인된 마크다운 문서 전부와 화면 파일 목록을 넣는다 (화면 HTML 본문은 넣지 않는다).
- 피드백 재생성이면 현재 본문과 피드백을 더한다.

단계 간 맥락은 CLI 세션이 아니라 이 입력으로 넘긴다. 그래서 단계마다 다른 에이전트를 써도 된다.

## 규칙

- **순서**: 위 생성 조건이 안 되면 생성 버튼이 비활성이고, API는 409를 돌려준다.
- **되돌리기 보관**: 본문이 있는 문서를 생성·재생성으로 교체할 때 교체 전 본문을 `previous_content`에 저장한다. 직접 편집 저장은 `previous_content`를 바꾸지 않는다. 되돌리면 `previous_content`를 비운다.
- **승인 조건**: 본문이 비어 있으면 승인할 수 없다.
- **동시 실행**: 같은 문서의 생성은 한 번에 하나만 돈다. 실행 중 재요청은 409.

## 예외

| 상황 | 처리 |
| --- | --- |
| 생성 중 에이전트 실패·중단, 브라우저 연결 끊김 | 기존 본문과 상태를 바꾸지 않는다. 부분 출력은 저장하지 않는다 |
| CLI 미설치·미로그인 | [agent-cli.md](agent-cli.md)의 안내 표시 |
| 되돌릴 내용 없음 | 되돌리기 버튼 비활성, API 409 |
| `0-PRODUCT.md` 기능 목록 규칙 위반 | 승인 불가, 위반 항목 표시 |

## 화면 상태

| 상태 | 표시 |
| --- | --- |
| `empty` | 에이전트 선택 + 생성 버튼 (생성 조건이 안 되면 비활성과 이유) |
| 생성 중 | 스트리밍 본문, 다른 조작 비활성 |
| `draft` | 편집기·미리보기, 피드백 입력, 되돌리기(가능할 때), 승인 버튼 |
| `approved` | 승인 표시, 다음 단계로 이동 |

요구사항 문서는 `4-USERFLOW.md` 다음에 목록으로 보여 주고, 문서마다 위 상태를 따른다. 시각 기준은 [2-DESIGN.md](../2-DESIGN.md).

## API (예정)

`:path`는 URL 인코딩한 문서 경로다 (예: `requirements%2Fproject.md`).

| 메서드·경로 | 요청 | 응답 |
| --- | --- | --- |
| `POST /api/projects/:id/documents/:path/generate` | `{ agent, feedback? }` | SSE — 생성 본문 |
| `PUT /api/projects/:id/documents/:path` | `{ content }` | 저장된 문서 |
| `POST /api/projects/:id/documents/:path/undo` | — | 복구된 문서 |
| `POST /api/projects/:id/documents/:path/approve` | — | `approved` 문서. `0-PRODUCT.md`면 생성된 요구사항 문서 목록 포함 |

## 완료·테스트 기준

- [ ] Codex로 `0-PRODUCT.md` 생성 → 직접 수정 → 피드백 재생성 → 승인이 된다.
- [ ] `0-PRODUCT.md` 승인 시 본문의 요구사항 링크대로 요구사항 문서가 `empty`로 생긴다. 링크가 없거나 `agents`면 승인되지 않는다.
- [ ] 같은 방식으로 `1` → `3` → `4` → 요구사항 문서들 → `changes/001-mvp.md`까지 승인된다.
- [ ] 생성 조건이 안 되는 문서는 생성할 수 없다 (UI 비활성, API 409).
- [ ] 피드백 재생성 후 되돌리기를 누르면 재생성 직전 본문으로 돌아온다.
- [ ] 생성이 실패해도 기존 본문이 남는다.
- [ ] 단계마다 다른 에이전트를 골라도 앞 문서 내용이 다음 문서에 반영된다.
- [ ] 생성된 문서가 문서 규칙을 따른다 — 구현 전 `예정` 표시, 기능 상세는 요구사항 문서로 링크.
