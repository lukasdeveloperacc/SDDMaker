# 화면 정의서

> 상태: 예정 ([changes/001-mvp.md](../changes/001-mvp.md))

## 목적

생성할 앱의 화면을 HTML 목업(`screens/<화면>.html`)으로 만든다. 사용자가 미리보기에서 컴포넌트를 고르거나 그림을 그려 위치를 짚고, 그 맥락을 정해진 템플릿으로 묶어 에이전트에게 수정·질문을 보낸다. 화면 파일 규칙은 [docs 규칙](../AGENTS.md#화면-정의서-screens).

생성 순서, 화면 목록 확정, 승인·승인 취소, 되돌리기, 동시 실행, API 공통 규칙은 [documents.md](documents.md)를 따른다. 이 문서는 화면 정의서만 다른 점을 적는다.

## 생성

- 생성 조건: 모든 요구사항 문서 승인 + 프로젝트에 디자인 문서 있음 ([documents.md](documents.md#생성-순서)). 디자인 문서가 없으면 생성 버튼 대신 **디자인 문서 만들기** 버튼으로 [디자인 단계](#디자인-단계)로 보낸다.
- 생성 입력: 기본 문서 + 디자인 문서 + 승인된 요구사항 문서 전부 + 대상 화면 이름 + 승인된 다른 화면 하나(있으면, [기준 화면](#디자인-단계)).
- 프롬프트는 [docs 규칙](../AGENTS.md#화면-정의서-screens)의 화면 파일 규칙 전부(스크립트·외부 파일 없음, 디자인 문서 토큰, 유일한 `data-component`, `data-frame`, 화면 간 링크, 자리표시·접근성·장식 금지)를 지키게 한다. 디자인 문서의 글꼴은 외부에서 불러오지 않고 대체 글꼴 목록으로 쓴다.
- 화면 간 링크를 걸 수 있게 생성 입력에 프로젝트의 화면 이름 목록을 함께 넣는다. 모바일 화면인지 웹 페이지인지는 에이전트가 앞 문서(대상 기기·플랫폼)를 보고 정해 `data-frame`에 적는다.
- 응답에서 HTML 꺼내기: 첫 ```` ```html ```` 블록, 없으면 응답 원문 전체.
- 전체 생성·피드백 재생성 결과는 서버가 끝나는 대로 초안으로 저장한다(직전 본문은 되돌리기로 남는다). 서버에는 DOM이 없어 정리하지 않고, `<script`·`on…=` 속성·`javascript:`가 있으면 저장하지 않고 오류로 알린다. 화면을 떠나도 이어지고, 서로 다른 화면은 동시에 3개까지 함께 만들 수 있다(요구사항 문서와 같은 공유 잠금). 주석 반영만 브라우저가 [결과 반영](#결과-반영) 절차로 정리해 저장한다.
- 전체 HTML 직접 편집도 저장 전에 같은 정리를 거친다.

## 디자인 단계

> 상태: 구현·자동 검증 완료 ([changes/015-design-prototype.md](../changes/015-design-prototype.md))

화면을 만들기 전에 디자인 문서를 먼저 만든다. 화면은 하나씩 따로 생성되어 기준 없이 만들면 화면마다 스타일이 갈리기 때문이다. 이 단계는 디자인 문서만 다루고, 화면(기준 화면 포함)은 **화면 정의서** 단계에서 만든다. 프로토타입 장치를 따로 두지 않는다. 기준 화면은 화면 정의서 중 처음 승인한 하나다.

- **위치**: 단계 목록의 **디자인 › 디자인 문서**(있음/없음 표시). 화면 목록이 정해지면 나타나고, 저장소 프로젝트는 처음부터 나타난다(디자인 문서는 승인된 요구사항 없이도 코드 기준으로 만들 수 있다). 화면 차례인데 디자인 문서가 없으면 이 단계가 먼저 열리고, 있으면 화면이 열린다.
- **구성**: 디자인 문서 편집기, 피드백(편집기에 내용이 있을 때, 선택), **생성**·**저장**·**변경 버리기**, 문서가 저장돼 있고 화면이 있으면 **화면 정의서로 이동**(승인 안 된 첫 화면).
- **작업본**: 편집기의 내용이 작업본이다. **저장**해야 프로젝트의 디자인 문서가 바뀌고, **변경 버리기**는 저장본으로 돌린다. 승인 상태는 없다. 저장하지 않은 변경은 화면 생성에 쓰이지 않는다.
- **생성**: 요구사항 문서를 모두 승인해야 한다 (화면 정의서 생성 조건에서 디자인 문서 있음만 뺀 것). 작업본을 `base`로 함께 보낸다. 결과는 서버가 저장하지 않고 편집기를 채운다. 사용자가 확인하고 저장한다. 빈 결과는 작업본을 바꾸지 않는다.
  - 작업본이 비어 있으면 승인된 기본 문서와 요구사항 문서로 새로 만든다. 형식은 DESIGN.md다(머리말 토큰 + 절).
  - 작업본이 있으면 — 처음에 붙여 넣은 문서 포함 — 그 문서를 반영해 만든다. 토큰 값(색·글꼴·간격·모서리)과 디자인 원칙은 그대로 두고, 요구사항에 필요하지만 없는 컴포넌트·상태와 대상 기기의 반응형·접근성만 덧붙인다. 머리말 키와 절 순서를 유지한다. 피드백을 적으면 피드백이 이 유지 규칙보다 우선한다.
- **나머지 화면**: 다른 화면을 생성할 때 승인된 다른 화면 하나(화면 이름 순 첫째, 자기 자신과 목록에서 빠진 화면 제외)의 HTML을 **기준 화면**으로 입력에 더한다. 배치 밀도·컴포넌트 모양·상태 표현을 따르게 하기 위해서다. 승인된 화면이 없으면 더하지 않는다.
- 디자인 문서를 고쳐도 이미 만든 화면은 그대로다. 바꾼 문서로 다시 만들려면 화면의 피드백 재생성을 쓴다.

### 토큰 CSS와 디자인 시스템 페이지

> 상태: 구현·자동 검증 완료 ([changes/019-design-system-page.md](../changes/019-design-system-page.md))

글로 된 디자인 문서만으로는 화면마다 컴포넌트 모양이 갈린다. 그래서 디자인 문서를 눈으로 보는 견본 페이지로 만들고, 화면이 그 견본을 그대로 가져다 쓰게 한다.

- **토큰 CSS**: 저장된 디자인 문서 맨 앞 YAML 머리말을 에이전트 없이 CSS 변수(`:root { --colors-primary: …; }`)로 바꾼다. 키는 `-`로 잇고 camelCase는 kebab-case로 바꾸며, 값 안의 `{colors.primary}` 참조는 `var(--colors-primary)`가 된다. 객체가 아닌 최상위 키(`name`·`description`)는 건너뛴다. 머리말이 없거나 읽지 못하면(getdesign.md 문서 등) 디자인 시스템 페이지 생성이 디자인 문서의 값을 `:root` 변수로 정의하게 하고, 그 페이지의 첫 `:root` 블록을 토큰 CSS로 쓴다. 머리말 토큰이 있으면 그것이 우선이다. 디자인 단계에서 접어 둔 상자로 보여 준다.
- **디자인 시스템 페이지**(`2-DESIGN.html`): 디자인 문서가 저장돼 있으면 디자인 단계 아래에 나온다. 기초(색·글꼴 단계·간격·모서리·그림자), 컴포넌트와 상태(기본·호버·포커스·비활성·오류·빈 상태), 요구사항에 나오는 패턴(폼·목록·표·대화상자·알림·빈 화면·오류 화면)을 한 페이지에 그린다. 입력은 저장된 디자인 문서 + 토큰 CSS + 디자인 문서 생성과 같은 앞 문서다. 화면 파일 규칙(스크립트·외부 파일 없음, `data-component`)을 지키고 `data-frame="page"`로 만든다.
  - 서버가 저장하므로 화면을 떠나도 이어 간다. 승인 상태와 되돌리기는 없다. 다시 생성하면 덮어쓴다. 피드백을 적으면 현재 페이지를 함께 보내 고친다.
  - 미리보기는 스크립트를 막은 iframe(`sandbox=""`)에 띄운다.
  - 디자인 문서를 바꿔도 페이지는 그대로다. 다시 생성해야 반영된다.
- **화면 생성 입력**: 토큰 CSS가 있으면 화면 `<style>` 맨 앞에 그 `:root` 블록을 그대로 넣고 값 대신 `var(--…)`를 쓰게 한다. 디자인 시스템 페이지가 있으면 같은 종류의 컴포넌트는 페이지의 마크업·클래스·스타일을 그대로 가져다 쓰게 한다. 기준 화면은 그대로 함께 넣는다.
- **내보내기·PR**: 토큰 CSS는 `docs/2-DESIGN.tokens.css`, 페이지는 `docs/2-DESIGN.html`로 넣는다 (있을 때만).

## 미리보기

- 스크립트가 돌지 않는 iframe(`sandbox="allow-same-origin"`, `allow-scripts` 없음)에 띄운다. 에이전트가 만든 HTML이 앱 안에서 실행되지 않게 하기 위해서다.
- 선택·그리기 표시는 iframe 바깥(앱 화면)에서 그린다.
- 화면 크기는 화면 파일의 `data-frame`을 따른다 ([docs 규칙](../AGENTS.md#화면-정의서-screens)). `mobile`은 390×844 프레임 안에서 스크롤한다. `page`는 **데스크톱(1280) / 휴대폰(390)** 폭 전환 버튼을 보여 준다.

## 프로토타입 이동

- 주석 모드가 꺼져 있을 때 화면 안의 `<a href="<화면>.html">`를 누르면, 앱이 클릭을 가로채 같은 프로젝트의 그 화면 미리보기로 넘어간다. 미리보기 위에 지나온 화면 경로와 **뒤로** 버튼을 보여 준다.
- 주석 모드가 꺼져 있으면 화면이 입력·스크롤을 직접 받는다(입력란에 타이핑하고, 휴대폰 프레임은 프레임 안에서 스크롤한다. 미리보기 사본에서만 넘침 숨김을 덮어쓰고 저장 HTML은 그대로다). 화면 프레임은 가운데에 두고, 링크로 이동하면 화면이 보이는 위치로 맞춘다.
- 프로젝트에 없는 화면으로 가는 링크는 이동하지 않고 "없는 화면"을 알린다. 외부 링크·그 밖의 링크는 이동하지 않는다.
- 화면을 열 때 없는 화면으로 가는 링크가 있으면 경고 목록으로 보여 준다. 승인을 막지는 않는다.
- 다른 화면으로 넘어가도 주석 목록은 화면별로 따로 유지된다 (새로고침하면 사라지는 것은 같다).

## 주석 모드

> (018 이후) 화면 정의서 화면에서 선택·그리기·이름으로 고르기·전체 HTML 편집과 주석 목록을 뺐다. 화면 다듬기는 [impeccable live](#impeccable-live)와 피드백 재생성으로 한다. 아래 주석 API·컴포넌트는 코드에 남아 있으나 화면에서 쓰지 않는다.

미리보기 위 도구 막대에서 **선택**과 **그리기** 중 하나를 켠다. 끄면 일반 미리보기다. `approved` 화면에서는 주석 모드를 쓸 수 없다 (승인 취소 후 사용).

### 선택

1. 마우스를 올리면 가장 가까운 `data-component` 요소에 테두리와 라벨(태그 · 컴포넌트 이름 · 텍스트 앞부분)이 표시된다.
2. 클릭하면 주석 팝업이 열린다. 팝업에는 태그와 컴포넌트 이름, **상위 컴포넌트로** 버튼(더 큰 영역을 고를 때)이 있다.
3. 요청 종류를 고른다 — **수정**(바꿀 내용) 또는 **질문**(바꾸지 않고 답만).
4. 설명을 적고 **추가**(⌘↵)를 누르면 주석 목록에 쌓인다.

도구 막대의 컴포넌트 선택 목록으로도 같은 주석 팝업을 열 수 있다. 키보드 사용자는 이 목록에서 컴포넌트를 고른다.

### 그리기

그리기는 포인터 입력으로만 지원한다. 키보드로 그림을 그리는 기능은 없으며, 키보드로 요청할 때는 컴포넌트 선택 목록을 사용한다.

1. 펜으로 미리보기 위에 자유롭게 그린다 (동그라미, 화살표 등).
2. 손을 떼면 주석 팝업이 열린다. 그린 영역과 겹치는 컴포넌트를 안쪽 것부터 최대 5개 보여 준다.
3. 요청 종류와 설명을 적고 추가한다. 그림은 주석이 지워질 때까지 미리보기 위에 남는다.
4. 그림 이미지는 보내지 않는다. 그린 영역의 좌표와 겹치는 컴포넌트만 텍스트로 보낸다 (이미지 첨부는 MVP 이후).

### 주석 목록

- 쌓인 주석을 순서대로 보여 준다. 항목마다 종류, 대상(컴포넌트 또는 그림), 설명이 있고 수정·삭제할 수 있다.
- 항목을 누르면 미리보기에서 해당 컴포넌트나 그림이 강조된다.
- **보내기 전 미리보기**로 서버가 조립한 요청(아래 템플릿)을 그대로 볼 수 있다.
- **보내기**를 누르면 실행 설정의 에이전트로 목록 전체를 요청 하나로 보낸다.
- 보내기 전 주석은 브라우저 메모리에만 있다. 새로고침하면 사라진다.

## impeccable live

> 상태: 구현·자동 검증 완료 ([changes/018](../changes/018-impeccable-live.md)). 브라우저에서 변형을 만들고 고르는 전체 흐름은 확인하지 않았다.

주석 모드보다 빠르게 화면을 다듬는 방법이다. [impeccable](https://impeccable.style)의 live 모드를 그대로 쓴다: 새 탭에서 화면 요소를 눌러 동작(polish·bolder·layout·typeset·colorize 등)이나 자유 입력을 고르고 **Go**를 누르면, 에이전트가 디자인 문서를 지키는 변형 3개를 그 자리에 끼워 보여 주고, 사용자가 넘겨 보며 조절해 **Accept**한다.

- 화면 정의서에서 **impeccable live로 다듬기**를 누르면 앱이 본문이 있는 화면 전부와 `PRODUCT.md`(0-PRODUCT.md)·`DESIGN.md`를 작업 폴더(`data/live/<프로젝트>`)로 내보내고, impeccable 보조 서버를 띄우고, 고른 에이전트(Claude Code·Codex)를 그 폴더에서 이벤트 대기 루프로 실행한다. live 화면은 화면 정의서 안에 바로 띄우고(앱과 다른 호스트 이름 `localhost`↔`127.0.0.1`로 띄워 앱과 격리한다), **새 탭에서 열기**로 따로 열 수도 있다. live가 열려 있는 동안 저장된 화면 미리보기와 피드백 재생성은 숨긴다. 탭이나 화면을 닫아도 세션은 이어지고 **live 종료**만 끝낸다.
- 작업 폴더의 변경은 **가져오기**를 눌러야 프로젝트에 들어간다. 주입한 스크립트는 지우고, 직전 본문은 되돌리기로 남긴다. 승인된 화면, 내보낸 뒤 앱에서 바뀐 화면, 변형을 고르는 중인 화면, Accept 뒤 에이전트의 정리(carbonize)가 끝나지 않은 화면, 스크립트가 든 화면은 가져오지 않고 이유를 보여 준다. 정리 전에 live를 끄면 다시 켤 때 에이전트가 남은 정리부터 마친다. 가져오지 않은 변경은 다시 열어도 덮어쓰지 않는다.
- **live 종료**는 에이전트와 보조 서버를 끄고 주입한 스크립트를 지운다. 작업 폴더와 가져오지 않은 변경은 남는다. 에이전트가 멈추면 **에이전트 다시 시작**으로 이어 간다.
- 보조 서버가 포트 하나(8400)를 쓰므로 앱 전체에서 한 번에 한 프로젝트만 열 수 있다. 이 에이전트는 작업 폴더에서 셸·파일 도구를 쓴다(Claude Code는 셸·읽기·쓰기 도구만, Codex는 샌드박스 없이). 문서 생성의 격리 실행과 다르다.

## 결과 반영

1. 응답이 끝나면 ```` ```html ```` 블록마다 최상위 요소의 `data-component`를 읽어, 현재 HTML에서 같은 이름의 요소를 통째로 바꾼다.
2. 다음 블록은 적용하지 않고 경고로 보여 준다 — 현재 HTML에 없는 이름, 최상위 요소가 둘 이상, 같은 응답에서 이미 바꾼 컴포넌트 안에 있는 컴포넌트(바깥 것만 적용).
3. 저장 전에 `<script>`·`<iframe>`·`<object>`·`<embed>` 요소와 `on*` 속성을 지운다.
4. 블록 밖 글(질문 답변, 설명)은 응답 패널에 보여 준다. 저장하지 않는다.
5. 하나라도 적용되면 `keepUndo: true`로 저장하고, 적용된 컴포넌트를 잠시 강조한다.
6. 하나라도 적용되면 주석 목록을 비운다. 아무것도 적용되지 않았으면 목록을 남긴다.

교체·정리는 브라우저에서 한다 (내장 `DOMParser` 사용, 서버에 HTML 파서를 두지 않는다). 서버는 안전장치로 화면 정의서 저장 요청에 `<script`가 있으면 거부한다(400).

## API (예정)

생성·저장·되돌리기·승인은 [documents.md](documents.md#api-예정)의 공통 API를 쓴다.

| 메서드·경로 | 요청 | 응답 |
| --- | --- | --- |
| `POST /api/projects/:id/documents/:path/annotations/preview` | `{ annotations }` | `{ prompt }` — 조립된 요청 |
| `POST /api/projects/:id/documents/:path/annotations` | `{ agent, annotations }` | SSE — 응답 원문 (서버는 저장하지 않음) |
| `POST /api/projects/:id/design/generate` | `{ agent, base?, feedback? }` | SSE — 디자인 문서 본문 (서버는 저장하지 않음, 저장은 `PUT /design`). `base` 생략 시 저장된 디자인 문서 |

| `POST /api/projects/:id/design/system` | `{ agent, feedback? }` | SSE — 디자인 시스템 페이지 HTML. 서버가 `project.designHtml`에 저장한다 (연결이 끊겨도 이어 감) |

디자인 시스템 페이지의 오류: 프로젝트 없음 404, 잘못된 `agent`·글이 아닌 `feedback`·페이지 없이 `feedback` 400, 저장된 디자인 문서 없음 `design_required` 409, 실행 중 `busy` 409. 결과에 HTML이 없거나 스크립트·이벤트 속성이 있으면 저장하지 않고 SSE `error`. 실행 잠금 종류는 `design`이다.

디자인 문서 생성의 오류: 프로젝트 없음 404, 잘못된 `agent`·글이 아닌 `base`/`feedback`·기준 문서 없이 `feedback` 400, 저장소 프로젝트·요구사항 미승인 `precondition` 409, 다른 작업 실행 중 `busy` 409. 실행 잠금 종류는 `design`이다.

`annotations` 항목: `{ kind: "change" | "question", target: { component, tag, text } | { drawing: { box, components } }, note }`. `box`는 문서 전체 대비 비율 `{ x1, y1, x2, y2 }`.

## 완료·테스트 기준

- [ ] 디자인 문서가 없으면 화면 정의서를 생성할 수 없고, 디자인 단계로 가는 버튼이 나온다.
- [ ] 디자인 단계에서 문서를 새로 만들면 결과가 편집기에만 채워지고, 저장하기 전에는 프로젝트의 디자인 문서가 바뀌지 않는다.
- [ ] 붙여 넣은 디자인 문서가 있으면 생성이 그 문서를 기준으로 삼아 토큰 값은 그대로 두고 필요한 것만 덧붙인다.
- [ ] 디자인 문서를 저장하면 화면 정의서 단계에서 화면을 만들고 미리보기·주석·승인을 쓸 수 있다. 디자인 단계에는 화면 패널이 없다.
- [ ] 승인된 화면이 있으면 다른 화면의 생성 입력에 그 HTML이 기준 화면으로 들어간다.
- [x] 디자인 문서 머리말이 토큰 CSS로 바뀌고, 화면 생성 입력과 내보내기(`docs/2-DESIGN.tokens.css`)에 들어간다.
- [x] 디자인 시스템 페이지를 만들면 서버가 저장하고, 이후 화면 생성 입력에 들어간다. 스크립트가 든 결과는 저장하지 않는다.
- [ ] 생성된 화면이 스크립트 없이 미리보기에 뜨고, 컴포넌트마다 `data-component`가 있다.
- [ ] 선택 모드에서 컴포넌트를 골라 수정 주석을 보내면 그 컴포넌트만 바뀌고 나머지 HTML은 그대로다.
- [ ] 그리기로 영역을 표시하면 겹치는 컴포넌트가 요청에 들어간다.
- [ ] 질문 주석만 보내면 HTML은 바뀌지 않고 답변만 보인다.
- [ ] 수정·질문·그림 주석을 섞어 한 번에 보낼 수 있고, 보내기 전에 조립된 요청을 볼 수 있다.
- [ ] 반영 후 되돌리기로 직전 HTML이 복구된다.
- [ ] 응답이나 직접 편집에 `<script>`·`<iframe>`·`on*` 속성이 있어도 저장된 HTML에는 남지 않는다.
- [ ] 생성된 화면에 `data-frame`이 있고, `mobile`은 390×844 프레임으로, `page`는 데스크톱·휴대폰 폭 전환으로 보인다.
- [ ] 미리보기에서 화면 간 링크를 누르면 그 화면으로 넘어가고 뒤로 돌아올 수 있다. 없는 화면 링크는 경고로 보인다.
- [ ] 내보낸 zip의 `screens/` 파일을 브라우저로 열어도 화면 간 링크로 넘어간다.
