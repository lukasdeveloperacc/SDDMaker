# 화면 정의서

> 상태: 예정 ([changes/001-mvp.md](../changes/001-mvp.md))

## 목적

생성할 앱의 화면을 HTML 목업(`screens/<화면>.html`)으로 만든다. 사용자가 미리보기에서 컴포넌트를 고르거나 그림을 그려 위치를 짚고, 그 맥락을 정해진 템플릿으로 묶어 에이전트에게 수정·질문을 보낸다. 화면 파일 규칙은 [docs 규칙](../AGENTS.md#화면-정의서-screens).

## 화면 목록 확정

`4-USERFLOW.md`를 승인할 때 본문의 `screens/<화면>.html` 링크를 모아 화면 목록을 만든다.

- 승인 화면에 뽑아낸 목록을 보여 준다. 목록을 바꾸려면 `4-USERFLOW.md` 본문을 고친다.
- 화면 이름은 영문 소문자·숫자·`-`만 쓴다. 어긋나면 승인할 수 없고 이유를 표시한다.
- 링크가 없으면(화면이 없는 앱) 화면 정의서 단계를 건너뛴다.
- `4-USERFLOW.md` 생성 프롬프트는 화면마다 `screens/<화면>.html` 링크를 넣게 한다.

## 생성

- 생성 조건: 모든 `requirements/` 문서 승인. 화면끼리는 순서가 없다 ([documents.md](documents.md#생성-순서)).
- 생성 입력: 문서별 공통 입력([documents.md](documents.md#생성-입력)) 중 고정 문서 4개 + 디자인 문서 + 승인된 요구사항 문서 전부 + 대상 화면 이름.
- 프롬프트는 [docs 규칙](../AGENTS.md#화면-정의서-screens)의 화면 파일 규칙(스크립트 없음, 외부 파일 없음, 컴포넌트마다 `data-component`)을 지키게 한다.
- 화면 전체 피드백 재생성, 전체 HTML 직접 편집, 되돌리기(1회분), 승인은 다른 문서와 같다 ([documents.md](documents.md#동작)).

## 미리보기

- 스크립트가 돌지 않는 iframe(`sandbox="allow-same-origin"`, `allow-scripts` 없음)에 띄운다. 에이전트가 만든 HTML이 앱 안에서 실행되지 않게 하기 위해서다.
- 선택·그리기 표시는 iframe 바깥(앱 화면)에서 그린다.

## 주석 모드

미리보기 위 도구 막대에서 **선택**과 **그리기** 중 하나를 켠다. 끄면 일반 미리보기다.

### 선택

1. 마우스를 올리면 가장 가까운 `data-component` 요소에 테두리와 라벨(태그 · 컴포넌트 이름 · 텍스트 앞부분)이 표시된다.
2. 클릭하면 주석 팝업이 열린다. 팝업에는 태그와 컴포넌트 이름, **상위 컴포넌트로** 버튼(더 큰 영역을 고를 때)이 있다.
3. 요청 종류를 고른다 — **수정**(바꿀 내용) 또는 **질문**(바꾸지 않고 답만).
4. 설명을 적고 **추가**(⌘↵)를 누르면 주석 목록에 쌓인다.

### 그리기

1. 펜으로 미리보기 위에 자유롭게 그린다 (동그라미, 화살표 등).
2. 손을 떼면 주석 팝업이 열린다. 그린 영역과 겹치는 컴포넌트를 안쪽 것부터 최대 5개 보여 준다.
3. 요청 종류와 설명을 적고 추가한다. 그림은 주석이 지워질 때까지 미리보기 위에 남는다.

### 주석 목록

- 쌓인 주석을 순서대로 보여 준다. 항목마다 종류, 대상(컴포넌트 또는 그림), 설명이 있고 수정·삭제할 수 있다.
- 항목을 누르면 미리보기에서 해당 컴포넌트나 그림이 강조된다.
- **보내기 전 미리보기**로 조립된 요청(아래 템플릿)을 그대로 볼 수 있다.
- 에이전트를 고르고 **보내기**를 누르면 목록 전체를 요청 하나로 보낸다.
- 보내기 전 주석은 브라우저에만 있다. 새로고침하면 사라진다.

## 요청 템플릿

서버가 주석 목록으로 아래 형태의 프롬프트를 조립한다. 사용자가 고치는 것은 주석이고, 템플릿 자체는 코드에 고정한다.

````text
대상 화면: screens/<화면>.html

## 요청
1. [수정] 컴포넌트 `filter-tabs` (button, "전체 229 · 제품명 229 · 의료용어 0")
   <사용자 설명>
2. [질문] 컴포넌트 `distribution-bar` (section, "분포 Train 4,981건 …")
   <사용자 설명>
3. [수정] 그림 — 영역 x 52%–71%, y 40%–48% / 겹치는 컴포넌트: `filter-tabs`, `legend`
   <사용자 설명>

## 응답 형식
- [수정] 요청마다 바뀐 컴포넌트의 HTML 전체를 ```html 블록 하나로 준다. 블록의 최상위 요소는 원래와 같은 data-component를 가진다.
- [질문]에는 블록 밖에 글로 답한다.
- 화면 파일 규칙을 지킨다 (스크립트 없음, 외부 파일 없음, 2-DESIGN 토큰).

## 현재 HTML
<화면 HTML 전체>

## 참고 문서
<고정 문서 4개 + 디자인 문서 + 관련 요구사항 문서>
````

- 그림 영역은 화면 폭·높이 대비 비율로 적는다.
- 컴포넌트 라벨의 텍스트는 앞 40자까지만 넣는다.

## 결과 반영

1. 응답이 끝나면 ```` ```html ```` 블록마다 최상위 요소의 `data-component`를 읽어, 현재 HTML에서 같은 이름의 요소를 통째로 바꾼다.
2. 현재 HTML에 없는 이름이거나 최상위 요소가 둘 이상인 블록은 적용하지 않고 경고로 보여 준다.
3. 적용 전에 `<script>` 요소와 `on*` 속성을 지운다.
4. 블록 밖 글(질문 답변, 설명)은 응답 패널에 보여 준다. 저장하지 않는다.
5. 하나라도 적용되면 저장하고, 바뀌기 전 HTML을 되돌리기용으로 보관한다. 적용된 컴포넌트를 잠시 강조한다.
6. 반영이 끝나면 보낸 주석 목록을 비운다. 적용되지 않은 블록이 있으면 해당 주석은 남긴다.

교체·정리는 브라우저에서 한다 (내장 `DOMParser` 사용, 서버에 HTML 파서를 두지 않는다). 화면 전체 생성·재생성 결과도 3번 정리를 거쳐 브라우저가 저장한다.

## 예외

| 상황 | 처리 |
| --- | --- |
| 응답에 적용할 블록이 하나도 없음 (수정 요청이 있었는데) | 저장하지 않고 경고. 주석 목록 유지 |
| `data-component`가 없는 HTML이 생성됨 | 저장은 하되 선택 모드에서 고를 컴포넌트가 없다고 표시. 전체 재생성으로 고친다 |
| 같은 `data-component` 이름이 둘 이상 | 경고 표시. 해당 이름은 선택·교체 대상에서 뺀다 |
| 에이전트 실패·연결 끊김 | 현재 HTML과 주석 목록을 그대로 둔다 |

## API (예정)

| 메서드·경로 | 요청 | 응답 |
| --- | --- | --- |
| `POST /api/projects/:id/documents/:path/generate` | `{ agent, feedback? }` | SSE — 화면 HTML. 화면은 서버가 저장하지 않는다 |
| `POST /api/projects/:id/documents/:path/annotations` | `{ agent, annotations: [{ kind: "change" \| "question", target: { component, tag, text } \| { drawing: { box, components } }, note }] }` | SSE — 응답 원문 |
| `PUT /api/projects/:id/documents/:path` | `{ content, keepUndo? }` | 저장된 문서. `keepUndo: true`면 바뀌기 전 본문을 되돌리기용으로 보관 |

`:path`, SSE 이벤트, 되돌리기·승인 API는 [documents.md](documents.md), [agent-cli.md](agent-cli.md)와 같다.

## 완료·테스트 기준

- [ ] `4-USERFLOW.md` 승인 시 본문의 화면 링크대로 화면 정의서가 `empty`로 생기고, 링크가 없으면 단계를 건너뛴다.
- [ ] 생성된 화면이 스크립트 없이 미리보기에 뜨고, 컴포넌트마다 `data-component`가 있다.
- [ ] 선택 모드에서 컴포넌트를 골라 수정 주석을 보내면 그 컴포넌트만 바뀌고 나머지 HTML은 그대로다.
- [ ] 그리기로 영역을 표시하면 겹치는 컴포넌트가 요청에 들어간다.
- [ ] 질문 주석만 보내면 HTML은 바뀌지 않고 답변만 보인다.
- [ ] 수정·질문·그림 주석을 섞어 한 번에 보낼 수 있고, 보내기 전에 조립된 요청을 볼 수 있다.
- [ ] 반영 후 되돌리기로 직전 HTML이 복구된다.
- [ ] 응답에 `<script>`나 `on*` 속성이 있어도 저장된 HTML에는 남지 않는다.
