# 내보내기

> 상태: 예정 ([changes/001-mvp.md](../changes/001-mvp.md))

## 목적

승인된 문서 세트를 `docs/` 폴더 구조 그대로 내려받아, 개발할 앱 저장소에 넣고 코딩 에이전트가 읽고 갱신할 수 있게 한다. 문서 원본은 DB에 있고, 내보내기는 복사본을 만든다.

## 동작

- 내보내기 탭에서 **zip 다운로드**를 누르면 브라우저가 zip 파일을 받는다.
- zip 구성:

```text
docs/
├── AGENTS.md                 # SDDMaker에 포함된 문서 규칙 (그대로)
├── 0-PRODUCT.md
├── 1-SYSTEM-ARCHITECTURE.md
├── 2-DESIGN.md               # 프로젝트에 디자인 문서를 넣은 경우만
├── 3-DATABASE.md
├── 4-USERFLOW.md
├── requirements/<기능>.md
├── screens/<화면>.html       # 화면이 있는 경우
└── changes/001-mvp.md
```

- 파일 이름: `<프로젝트 이름>-docs.zip`

## 규칙

- 생성 대상 문서([documents.md](documents.md)의 생성 순서 전부)가 모두 `approved`일 때만 내보낼 수 있다. 아니면 버튼이 비활성이고 승인되지 않은 문서를 표시한다.
- 서버는 사용자 폴더에 파일을 쓰지 않는다. 경로 설정도 없다.

## 예외

| 상황 | 처리 |
| --- | --- |
| 승인되지 않은 문서가 있음 | API 409, 화면에 해당 문서 목록 |
| 프로젝트 이름에 파일 이름으로 쓸 수 없는 문자 | 해당 문자를 `-`로 바꾼다 |

## API (예정)

| 메서드·경로 | 응답 |
| --- | --- |
| `GET /api/projects/:id/export` | `application/zip` 첨부 파일 |

## 완료·테스트 기준

- [ ] 모든 문서를 승인하면 zip을 받을 수 있고, 위 구조와 승인된 본문 그대로 들어 있다.
- [ ] 디자인 문서를 넣은 프로젝트만 `docs/2-DESIGN.md`가 들어간다.
- [ ] 하나라도 승인되지 않았으면 내보낼 수 없다.
