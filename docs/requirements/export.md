# 내보내기

> 상태: 기존 수동 흐름을 유지하며 014 서버 기능은 구현되어 표적 자동 검증을 통과했다. UI는 구현되어 컴포넌트 검증을 통과했고 전체 테스트·타입 검사·린트·빌드는 통과했다. 브라우저 조작은 문서 확정 시점에 미검증이다 ([014](../changes/014-core-scenarios.md)). 기존 결과는 [001](../changes/001-mvp.md)에 보존한다.

## 목적

승인된 문서 세트를 `docs/` 폴더 구조 그대로 내려받아, 개발할 앱 저장소에 넣고 코딩 에이전트가 읽고 갱신할 수 있게 한다. 문서 원본은 DB에 있고, 내보내기는 복사본을 만든다.

## 동작

- 내보내기 탭에서 **zip 다운로드**를 누르면 브라우저가 zip 파일을 받는다.
- zip 구성:

```text
docs/
├── AGENTS.md                 # 저장소 원본 규칙, 없으면 앱 규칙
├── 0-PRODUCT.md
├── 1-SYSTEM-ARCHITECTURE.md
├── 2-DESIGN.md               # 프로젝트에 디자인 문서가 있는 경우
├── 3-DATABASE.md
├── 4-USERFLOW.md
├── requirements/<기능>.md
├── screens/<화면>.html       # 화면이 있는 경우
└── changes/001-mvp.md
```

- 파일 이름: `<프로젝트 이름>-docs.zip`
- 저장소 프로젝트는 `changes/001-mvp.md` 대신 `changes/001-baseline.md`를 담는다 ([github.md](github.md#저장소-프로젝트의-생성)).
- 저장소 프로젝트는 같은 파일 구성을 저장소에 PR로 올릴 수도 있다 ([github.md](github.md#pr-올리기)).

## 규칙

- 생성 대상 문서([documents.md](documents.md#생성-순서)의 생성 순서 전부)가 모두 `approved`이고, "목록에서 빠짐" 문서가 없을 때만 내보낼 수 있다. 아니면 버튼이 비활성이고 걸리는 문서를 표시한다.
- "앞 문서 변경됨" 표시는 내보내기를 막지 않는다. 다만 화면에 경고로 보여 준다.
- 서버는 사용자 폴더에 파일을 쓰지 않는다. 경로 설정도 없다.
- 파일 이름은 프로젝트 이름에서 문자·숫자·`-`·`_` 외의 글자를 `-`로 바꿔 만든다. 한글 이름을 위해 `Content-Disposition`에 `filename*=UTF-8''…`(RFC 5987)를 함께 보낸다.

## 예외

| 상황 | 처리 |
| --- | --- |
| 승인되지 않은 문서·목록에서 빠진 문서가 있음 | API 409, 화면에 해당 문서 목록 |

## API

| 메서드·경로 | 응답 |
| --- | --- |
| `GET /api/projects/:id/export` | `application/zip` 첨부 파일 |

## 완료·테스트 기준

- [ ] 모든 문서를 승인하면 zip을 받을 수 있고, 위 구조와 승인된 본문 그대로 들어 있다.
- [ ] 디자인 문서가 있는 프로젝트만 `docs/2-DESIGN.md`가 들어간다.
- [ ] 하나라도 승인되지 않았거나 목록에서 빠진 문서가 있으면 내보낼 수 없다.
- [ ] 한글 프로젝트 이름도 다운로드 파일 이름이 깨지지 않는다.

## R5 저장소 원본 규칙 보존

- ZIP과 PR은 [`src/server/export.ts`](../../src/server/export.ts)의 공통 `exportFiles` 파일 구성기를 사용한다. PR 전용 처리로 끝내지 않는다. 저장소 기준 커밋에 원래 `docs/AGENTS.md`가 있으면 그 내용을 UTF-8 BOM과 LF/CRLF 줄바꿈까지 보존해 그대로 전달한다. **원본이 없을 때만** 앱 `docs/AGENTS.md`를 대체 규칙으로 넣는다. 비저장소는 기존 앱 규칙을 쓴다.
- 원래 규칙이 symlink·비텍스트이거나 안전하게/허용 범위 내에서 읽을 수 없는 경우, 앱 규칙으로 조용히 교체하지 않는다. ZIP/PR 모두 `export_blocked` 409와 `items`의 해당 경로로 중단한다. 원래 규칙은 생성 프롬프트의 지시로 실행하지 않는다.
- 원래 DESIGN은 사용자 입력이 없으면 PR에서 보존한다. 사용자가 입력한 디자인만 기존처럼 ZIP의 `docs/2-DESIGN.md`에 포함한다. PR에서는 생성 대상 밖 원래 문서를 지우거나 고치지 않는다.
- 전체 초안 완료는 내보내기 권한이 아니다. 기존의 실제 `approved` 문서 조건과 목록에서 빠진 문서 차단을 유지한다. 배치의 비활성 요구사항을 생성 문맥에서 제외하는 규칙은 기존 내보내기 차단을 없애지 않는다.
- 실패/취소/재시작/오래된 저장소 기준에서도 현재 프로젝트와 초안을 보존하지만, ZIP은 실제 승인 후에만 가능하다. 승인 전 ZIP/자동 승인 경로는 추가하지 않는다.

### R5 내보내기 수용 기준 (통합 검증 기준)

- [ ] ZIP을 풀어 기존 규칙 원문과 바이트 단위 일치를 확인하고, 같은 구성기를 쓰는 로컬 PR도 동일하게 보존한다.
- [ ] 규칙이 없을 때만 앱 규칙이 들어가며 읽을 수 없는 기존 규칙은 ZIP/PR 모두 `export_blocked/items`로 중단한다.
- [ ] 미승인 초안/목록에서 빠진 문서는 계속 차단하고, 디자인/한글 파일명/기존 승인 ZIP 회귀가 없다.

서버 표적 검증 결과는 [014 검증 결과](../changes/014-core-scenarios.md#검증-방법과-결과)에 기록한다. 체크리스트는 수용 기준이며 자동 검증 결과와 브라우저 관찰을 구분한다. 브라우저·독립 검토 결과는 별도 실행 증거로 관리한다.
