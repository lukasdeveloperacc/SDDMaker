# 프로젝트

> 상태: 예정 ([changes/001-mvp.md](../changes/001-mvp.md))

## 목적

SDD 문서를 만들 앱 하나를 프로젝트로 등록하고, 진행 상태를 앱을 껐다 켜도 이어 갈 수 있게 한다.

## 동작

- **목록**: 프로젝트 이름, 생성 시각, 진행 상태(인터뷰 상태, 승인된 문서 수 / 전체 문서 수)를 보여 준다.
- **생성**: 이름과 아이디어를 입력하면 프로젝트와 기본 행 5개(기본 문서 4개 + `changes/001-mvp.md`)를 `empty`로 만들고 프로젝트 상세로 이동한다 ([3-DATABASE.md](../3-DATABASE.md#documents)).
- **디자인 문서**: 생성 시 `DESIGN.md` 마크다운을 붙여 넣는다. 프로젝트 상세 상단에는 디자인 카드를 두지 않는다. 디자인 문서가 없으면 화면 정의서 생성 단계에서만 입력란을 제공한다.
  - 가진 디자인 문서가 없으면 [getdesign.md](https://getdesign.md/)에서 만들 앱에 가장 가까운 것 하나를 골라 그 `DESIGN.md`를 복사해 붙여 넣는다. 입력란 옆에 이 링크와 안내를 보여 준다. 앱이 사이트에서 가져오거나 대신 고르지 않는다.
  - 생성 입력과 `2-DESIGN.md` 내보내기에 그대로 쓰며, SDDMaker가 고치지 않는다.
  - 화면 정의서를 만들기 전까지는 넣어야 한다 ([screens.md](screens.md#생성)). 화면이 없는 앱은 없어도 된다.
- **상세**: 단계 목록(인터뷰 · 기본 문서 · 요구사항 문서 · 화면 정의서 · 변경 기록 · 내보내기)을 보여 준다. 화면 공통 기준은 [2-DESIGN.md](../2-DESIGN.md).
- **삭제**: 확인 창에서 프로젝트 이름을 다시 입력하면 프로젝트와 인터뷰·문서를 모두 지운다. 실행 중인 에이전트가 있으면 먼저 종료한다.

## 규칙

- 이름과 아이디어는 공백만으로 채울 수 없다.
- 디자인 문서를 바꾸면 이후 생성부터 반영된다. 이미 만든 문서는 그대로다.
- 화면 정의서 행이 있으면 디자인 문서를 비울 수 없다 (409). 바꾸는 것은 된다.
- 삭제는 되돌릴 수 없다.

## 예외

| 상황 | 처리 |
| --- | --- |
| 이름·아이디어 비어 있음 | 400, 화면에서 입력 오류 표시 |
| 삭제 확인 이름 불일치 | 삭제 버튼 비활성 |
| 없는 프로젝트 ID | 404 |

## API (예정)

| 메서드·경로 | 요청 | 응답 |
| --- | --- | --- |
| `GET /api/projects` | — | 프로젝트 목록 + 진행 상태 |
| `POST /api/projects` | `{ name, idea, designMd? }` | 생성된 프로젝트 |
| `GET /api/projects/:id` | — | 프로젝트, 인터뷰(메시지 포함), 문서 목록(상태·표시 포함) |
| `PUT /api/projects/:id/design` | `{ designMd }` | 저장된 디자인 문서 (빈 값이면 제거) |
| `DELETE /api/projects/:id` | — | 204 |

## 완료·테스트 기준

- [ ] 프로젝트를 만들면 목록에 나타나고, 기본 행 5개가 `empty`로 생긴다.
- [ ] 디자인 문서 입력란 옆에 getdesign.md 링크가 있고, 붙여 넣은 내용이 그대로 저장된다.
- [ ] 앱을 재시작해도 프로젝트, 인터뷰 기록, 문서 본문, 승인 상태가 그대로다.
- [ ] 빈 이름·아이디어로는 만들 수 없다.
- [ ] 프로젝트를 삭제하면 목록과 DB에서 인터뷰·문서까지 사라지고, 실행 중이던 CLI 프로세스가 남지 않는다.
