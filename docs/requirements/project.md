# 프로젝트

> 상태: 예정 ([changes/001-mvp.md](../changes/001-mvp.md))

## 목적

SDD 문서를 만들 앱 하나를 프로젝트로 등록하고, 진행 상태를 앱을 껐다 켜도 이어 갈 수 있게 한다.

## 동작

- **목록**: 프로젝트 이름, 생성 시각, 진행 상태(인터뷰 상태, 승인된 문서 수 / 전체 문서 수)를 보여 준다.
- **생성**: 이름과 아이디어를 입력하면 프로젝트와 `empty` 상태 고정 문서 5개를 만들고 프로젝트 상세로 이동한다 ([3-DATABASE.md](../3-DATABASE.md#documents)).
- **디자인 문서**: 생성 시 또는 상세에서 마크다운을 붙여 넣는다 (선택). 생성 입력과 `2-DESIGN.md` 내보내기에 그대로 쓰며, SDDMaker가 고치지 않는다.
- **상세**: 단계 목록(인터뷰 · 고정 문서 · 요구사항 문서 · 변경 기록 · 내보내기)을 보여 준다. 화면 공통 기준은 [2-DESIGN.md](../2-DESIGN.md).

## 규칙

- 이름과 아이디어는 공백만으로 채울 수 없다.
- 디자인 문서를 바꾸면 이후 생성부터 반영된다. 이미 승인된 문서는 그대로다.

## 예외

| 상황 | 처리 |
| --- | --- |
| 이름·아이디어 비어 있음 | 400, 화면에서 입력 오류 표시 |
| 없는 프로젝트 ID | 404 |

## API (예정)

| 메서드·경로 | 요청 | 응답 |
| --- | --- | --- |
| `GET /api/projects` | — | 프로젝트 목록 + 진행 상태 |
| `POST /api/projects` | `{ name, idea, designMd? }` | 생성된 프로젝트 |
| `GET /api/projects/:id` | — | 프로젝트, 인터뷰(메시지 포함), 문서 목록 |
| `PUT /api/projects/:id/design` | `{ designMd }` | 저장된 디자인 문서 (빈 값이면 제거) |

## 완료·테스트 기준

- [ ] 프로젝트를 만들면 목록에 나타나고, 고정 문서 5개가 `empty`로 생긴다.
- [ ] 디자인 문서를 넣고 빼는 것이 저장된다.
- [ ] 앱을 재시작해도 프로젝트, 인터뷰 기록, 문서 본문, 승인 상태가 그대로다.
- [ ] 빈 이름·아이디어로는 만들 수 없다.
