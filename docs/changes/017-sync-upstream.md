# 017 앞 문서 변경 반영 (동기화)

> 상태: 구현·자동 검증 완료 (2026-11-04). 실제 에이전트가 만든 갱신본의 품질은 확인하지 않았다.

## 이유

앞 문서(예: `4-USERFLOW.md`)를 고치면 뒤 문서에 "앞 문서 변경됨" 표시만 붙고, 반영은 문서마다 승인 취소 → 재생성 → 재승인을 손으로 해야 했다(요구사항 12개면 12번). 요구사항은 기본 문서 4개를, 화면은 기본 문서와 요구사항을 입력으로 받으므로 의존이 실제로 있다.

## 범위

- `POST /api/projects/:id/sync`와 사이드바의 **앞 문서 변경 반영 · N개** 버튼 ([documents.md](../requirements/documents.md#앞-문서-변경-표시)).
- 요구사항 → 화면 순서, 각 단계 동시 3개, 현재 본문 기준으로 어긋난 부분만 수정, 결과는 초안 + 되돌리기.
- 검사: 문서마다 에이전트가 어긋남을 검사하고, 고칠 곳이 없으면 `변경 없음`으로 답해 표시만 지운다(호출 한 번).
- 자동 실행: 기본 문서가 모두 승인되고 표시된 문서가 있으면 프로젝트 화면이 자동으로 `sync`를 호출한다. 문서마다 자동 시도는 한 번, 사이드바 체크박스로 끌 수 있다.

## 제외 범위

- 서버가 화면 없이 스스로 시작하는 실행(화면을 연 브라우저가 시작한다), 변경 기록 갱신, 기본 문서 간 연쇄 갱신(앞 기본 문서는 사람이 직접 고친다), 변경 내용 diff 미리보기, 자동 재승인.
- 화면 HTML 서버 정리(파서 없음). 위험한 패턴은 거절한다.

## 검증

- 서버: 요구사항→화면 순서와 초안화·되돌리기·표시 해제, 화면 입력에 갱신본 포함, 스크립트가 든 화면 거절, 표시 없음 409, USERFLOW 미승인 409. 컴포넌트: 버튼의 개수·숨김·비활성.
- 전체 52파일·673개 테스트, 타입 검사, 린트 통과.
- 확인하지 않은 것: 실제 Claude/Codex 출력(`변경 없음` 지시를 따르는지 포함), 브라우저 조작, 저장소 프로젝트.
