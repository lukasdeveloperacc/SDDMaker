# 003 에이전트 로그인 저장소 격리

> 상태: 완료

## 변경 이유와 범위

두 CLI의 로그인이 호스트 사용자 설정에 종속되지 않도록 한다. Codex뿐 아니라 Claude도 SDDMaker 데이터 폴더 아래 전용 저장소를 사용한다. 로그인·상태 확인·생성에 같은 환경을 전달하고, Docker의 대화형 로그인 명령도 같은 경로를 사용한다.

호스트 로그인 파일을 복사하거나 토큰을 앱에서 취급하지 않는다. 최초 인증은 공식 CLI에서 사용자가 진행한다. Codex sandbox 권한 변경은 범위에 포함하지 않는다.

## 구현과 검증

- 상속된 CLI 홈 환경변수를 전용 경로로 덮어쓰는 회귀 테스트를 먼저 추가한다.
- Claude 홈을 데이터 폴더에 만들고 CLI 자식 환경과 Docker 환경에 적용한다.
- 앱·README의 로그인 안내와 아키텍처·요구사항의 기존 Claude 전역 로그인 설명을 갱신한다.
- 테스트·린트·타입 검사·Docker 빌드와 격리된 로그인 상태·저장 경로를 확인한다.

## 결과

- 호스트 홈 설정을 덮어쓰는 회귀 테스트가 기존 코드에서 실패하고 수정 후 통과했다. 전체 279개 테스트·린트·타입 검사와 Linux arm64 Docker 이미지 빌드가 통과했다.
- 새 이미지에서 실제 CLI의 상태 확인을 실행했다. Claude는 `/app/data/claude-home`을 설정 경로로 보고하고, 두 CLI 모두 별도 인증 전 미로그인 상태다. 두 전용 경로는 비루트 사용자에게 쓰기 가능하다.
- 별도 Compose 프로젝트에서 가짜 CLI 문서 생성·승인·ZIP 내보내기, 컨테이너 재생성 후 DB와 두 CLI 전용 저장소 유지, 테스트 프로젝트 삭제까지 통과했다. 검증용 볼륨만 정리했다.
- 기본 Compose 서비스도 새 이미지로 재생성했고 `http://127.0.0.1:3000`에서 healthy 상태다. 앱의 상태 API와 터미널 로그인 명령은 같은 전용 경로를 사용한다. 읽기 전용 코드 리뷰도 PASS다.
- 실제 계정 인증·모델 생성은 수행하지 않았다. 최초 계정 인증은 [README](../../README.md)의 컨테이너 명령으로 진행한다. 기존 Claude 로그인 파일은 삭제·이동하지 않으며 새 경로에서 재인증이 필요하다. Docker의 Codex sandbox 제한은 [002 기록](002-docker.md)에 남아 있다.

현재 실행·저장소 규칙은 [시스템 아키텍처](../1-SYSTEM-ARCHITECTURE.md), 로그인 동작은 [에이전트 CLI 요구사항](../requirements/agent-cli.md)을 따른다.
