# 006 실제 로그인 터미널과 충돌 복구

> 상태: 완료

## 원인과 범위

다른 창이나 이전 연결의 로그인이 남아 있으면 POST는 409를 반환하지만 화면은 로그인 콘솔을 지우고 오류 문장만 보여 줬다. 진행 중인 로그인을 종료할 방법이 없었다. 또한 DELETE가 자식 프로세스 종료 전에 응답해 빠른 재연결과 충돌했다. 이미 끊긴 요청의 abort 신호를 뒤늦게 구독하는 경우에도 종료 전달이 누락될 수 있었다.

출력과 한 줄 입력을 흉내 내던 콘솔을 실제 PTY와 xterm.js 터미널로 교체했다. 계정 연결 버튼은 고정된 공식 로그인 명령을 PTY에서 실행한다. 키 입력·붙여넣기·방향키·제어 문자와 터미널 크기 변경을 그대로 전달한다. 긴 안내와 중복 코드 입력폼은 없애고 필요한 인증 도움말만 툴팁으로 둔다. 범용 셸은 제공하지 않는다.

진행 상태를 에이전트 조회에 포함하고 기존 로그인 종료 후 재연결을 제공한다. 취소 API는 실제 세션 해제를 기다린다. 이미 끊긴 요청은 자식 실행 전에 중단한다. 로그인 시작·충돌·종료는 인증 값 없이 메타데이터만 서버 로그에 남긴다. macOS 설치 시 node-pty helper 실행 권한을 보정하고 Docker standalone 빌드에서는 네이티브 PTY 실행을 검사한다.

## 검증 기준

- 자식 CLI의 stdin/stdout이 실제 TTY이며 ANSI 출력·raw 키 입력·resize가 보존된다.
- 브라우저에서 터미널을 직접 클릭해 입력·붙여넣기·방향키·Ctrl+C가 동작한다.
- node-pty 네이티브 바이너리와 helper가 Docker standalone에 포함되어 실행된다.
- 진행 중 세션이 화면 초기 조회와 409 응답에서 드러나고 종료 후 다시 연결할 수 있다.
- 취소 응답 204 직후 재시작이 성공하고, 종료를 기다리는 동안 중복 클릭을 막는다.
- 이미 중단된 요청은 자식 프로세스를 만들지 않고 잠금을 해제한다.
- 로그에는 인증 URL·코드·토큰·CLI 출력이 포함되지 않는다.
- 회귀 테스트·린트·타입 검사·Docker 빌드 및 실제 HTTP 취소·재연결 확인.

## 결과

- 전체 25개 파일의 312개 테스트, 린트, 타입 검사를 통과했다. 별도 코드 리뷰에서도 필수 수정 사항이 없었다.
- 가짜 CLI와 실제 네이티브 PTY를 연결한 브라우저에서 키 입력·붙여넣기·방향키·Ctrl+C·크기 변경과 두 번째 창의 충돌 복구를 확인했다. 데스크톱과 390px 화면에서 가로 넘침 없이 표시된다.
- Docker 이미지 빌드와 standalone PTY 검사를 통과했다. 격리된 임시 컨테이너의 실제 Claude/Codex CLI 모두 인증 URL 출력·raw 입력·resize·종료·즉시 재연결을 확인했다. 인증 URL과 코드는 검증 로그에 출력하지 않았다.
- 최종 Compose 컨테이너가 healthy이며 비루트 사용자로 네이티브 PTY를 실행했다. 3000번 포트의 실제 화면에서 긴 안내 제거·툴팁의 키보드 포커스 표시·모바일 가로 폭을 재확인했다.
- 실제 계정의 브라우저 인증 완료와 인증 후 모델 실행은 검증하지 않았다.
