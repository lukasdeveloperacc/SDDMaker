# 016 요구사항 병렬 생성과 이탈 후 유지

> 상태: 구현·자동 검증 완료 (2026-11-04). 실제 에이전트의 동시 실행 속도와 구독 사용량 한도 영향은 확인하지 않았다.

## 이유

요구사항 문서는 입력이 겹치지 않는데(기본 문서만 본다) 프로젝트당 실행 하나라는 잠금 때문에 하나씩만 만들 수 있었다. 저장소 프로젝트의 일괄 초안(요구사항 8개)은 순차로 약 8분이 걸렸다(문서당 53~141초, 중앙값 약 60초). 또 생성 중 화면을 떠나면 생성이 취소되고 진행도 보이지 않았다.

## 범위

- 새 프로젝트의 **남은 요구사항 N개 한 번에 만들기**: 동시 3개, 잠금은 하나, 문서마다 끝나는 대로 초안 저장 ([documents.md](../requirements/documents.md#규칙)).
- 마크다운 문서 생성과 위 실행은 연결이 끊겨도 이어진다. `DELETE /api/projects/:id/run`으로 취소한다.
- 요구사항 문서를 하나씩 따로 생성하는 것도 동시에 된다(같은 실행 잠금을 공유, 동시 3개까지). 기본 문서·화면 정의서·디자인은 여전히 하나씩이다.
- 진행 표시: 단계 목록의 움직이는 **생성 중** 배지 하나만 쓴다(상단 배너는 두지 않는다). 생성 버튼을 누르면 곧바로 배지가 바뀌고, 상태 변화는 `GET /api/projects/:id/events`(SSE)로 실시간 반영한다. `prefers-reduced-motion`이면 움직이지 않는다.

## 제외 범위

- 기본 문서(`1-ARCHITECTURE`→`3-DATABASE`→`4-USERFLOW`)의 병렬화: 앞 문서가 입력이다.
- 화면 정의서 병렬 생성, 문서별 독립 잠금(프로젝트당 실행 하나 구조 유지. 요구사항 문서끼리만 잠금을 공유한다), 동시 개수 설정.
- 저장소 프로젝트의 일괄 초안 병렬화.

## 검증

- 서버 테스트: 동시 3개 상한, 일부 실패·전부 실패, 직접 쓴 문서 보존, 연결 끊김 후 완료, 취소 경로, 진행 노출, 요구사항 문서 개별 동시 생성, 이벤트 스트림. 컴포넌트 테스트: 단계 목록의 생성 중 배지. 기존 "연결이 끊기면 취소" 테스트 3개를 새 동작(취소 경로로만 취소)으로 바꿨다.
- 브라우저(가짜 CLI, 문서당 5초 지연): 시작 후 다른 단계로 이동해도 생성 중 배지가 보이고(버튼 클릭 후 약 270ms), 요구사항 두 문서를 동시에 생성해 초안으로 끝난다.

## 결과

- 전체 테스트·타입 검사·린트·빌드 통과.
- 확인하지 않은 것: 실제 Claude/Codex 동시 3개 실행(같은 작업 폴더를 공유한다)의 속도·한도.
