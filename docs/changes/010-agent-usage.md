# 010 에이전트 사용량 표시

> 상태: 완료 (2026-10-20)

## 이유

인터뷰·문서 생성은 사용자의 구독 한도를 쓴다. 한도가 얼마나 남았는지 앱에서 보이지 않으면 생성 도중 한도에 걸리거나 에이전트를 고를 기준이 없다. 남은 양을 보고 Claude·Codex를 나눠 쓸 수 있게 한다.

## 범위

- 상단 바에 로그인된 에이전트마다 사용량 한 줄을 둔다: `<에이전트> ▬▬▭▭ 45% 2h 12m · 38% 5d 7h`. 막대와 첫 값은 5시간 한도, 두 번째 값은 주간 한도이며 남은 시간은 초기화까지다.
- 값은 공식 CLI가 주는 것만 쓴다. 앱은 토큰을 읽지 않는다 ([agent-cli.md](../requirements/agent-cli.md#사용량)).

관련 기준: [에이전트 연동](../requirements/agent-cli.md#사용량), [아키텍처](../1-SYSTEM-ARCHITECTURE.md#사용량).

## 제외 범위

- 사용량 기록·그래프, 한도 근접 알림, 한도에 따른 자동 에이전트 전환.
- 토큰 수·비용 표시.

## 구현 전 확인할 것

2026-10-20 컨테이너에서 Claude Code 2.1.303·codex-cli 0.162.1 실제 계정으로 확인했다.

- [x] Claude `-p` 실행에서 `rate_limit_event`가 온다. 5시간·주간은 `rate_limit_info.unifiedWindows.five_hour`·`seven_day`로 함께 오고, 각각 `utilization`(0–1)과 `resetsAt`(unix 초)이 있다. 확인한 값은 0이었고, 0–1 비율이라는 근거는 CLI 안의 임계값 정의(`utilization:0.75` 등)다.
- [x] `codex app-server`의 `account/rateLimits/read`가 앱 전용 `CODEX_HOME`에서 모델 실행 없이 응답한다. 확인한 계정은 주간 한도만 있었다(primary 10080분, secondary 없음).

## 작업

- 서버 `usage.ts`: Claude 실행 출력의 `rate_limit_event`를 메모리에 저장하고, Codex는 조회 때 `app-server`로 읽는다. 구독 로그인이 아니면 `null`.
- API `GET /api/agents/usage`.
- 상단 바 `AgentUsage`: 화면을 열 때와 실행이 끝나거나 연결이 바뀔 때 다시 읽고, 1분마다 남은 시간을 다시 계산한다.
- 결정: 막대 길이는 5시간, 없으면 주간 한도. 막대 색과 600px 이하 축약 값은 초기화 시각이 지나지 않은 두 한도 중 높은 비율. Codex 칸은 `windowDurationMins` 1440 이하면 5시간, 같은 칸이면 primary 우선. 초기화 시각이 지난 값은 `—`.
- 상단 바는 920px 이하에서 사용량을 별도 줄로 내린다.
- 가짜 CLI에 사용량 출력을 추가하고 서버·컴포넌트 테스트를 추가했다.

## 검증

- 가짜 CLI 출력으로 두 에이전트의 값 파싱, 값 없음, 미로그인 시 숨김을 테스트한다.
- 실행 후 Claude 값이 갱신되고, 화면을 열 때 Codex 값이 갱신되는지 브라우저 1122px·390px에서 확인한다. 390px에서 가로 넘침이 없어야 한다.
- 린트·타입 검사·전체 테스트·Docker 빌드.

## 결과

- 리뷰 3차에서 모두 통과했다. 1차 수정: 중간 폭 배치, 좁은 화면의 색·값, null 줄 방어. 2차 수정: 920px 기준.
- 가짜 CLI와 브라우저 1122·921·920·900·390px에서 확인했다. 가로 스크롤이 없고, 실행·로그인·로그아웃 뒤 막대가 갱신된다.
- 실행 중인 앱에서 실제 계정으로는 아직 확인하지 않았다. 컨테이너를 다시 배포해야 한다.
- 알려진 한계: 601–605px에서 가장 긴 문구가 줄 안에서 두 줄로 접힌다. Codex 읽기가 멈추면 사용량 줄 전체가 최대 10초 늦게 나온다.
- 함께 고친 것: `claude.ts`·`codex.ts`가 null이거나 객체가 아닌 JSON 줄을 건너뛴다.
