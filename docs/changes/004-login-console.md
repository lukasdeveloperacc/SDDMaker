# 004 웹 로그인 콘솔

> 상태: 완료

## 이유와 범위

Claude의 컨테이너 로그인은 브라우저에서 받은 인증 코드를 실행 중인 CLI에 돌려줘야 한다. 기존 화면에는 입력 경로가 없어 터미널로 이동해야 했다. Claude·Codex 모두 공식 로그인 명령의 출력을 웹 콘솔에서 보고 인증할 수 있게 한다. 범용 셸이나 자체 OAuth, 새 터미널 의존성은 추가하지 않는다. 기존 전용 인증 저장소와 프로세스 종료 정책을 유지한다.

## 구현과 검증

- 로그인 출력은 개행을 기다리지 않고 SSE로 전달해 터미널 패널에 표시한다.
- Claude에 한해 전체 인증 코드(`code#state`)를 현재 로그인 세션의 stdin에 한 번 전달하고 입력을 닫는다. 불완전한 코드는 전달 전에 거부한다. 세션 식별자를 확인하며 입력·출력은 DB·서버 로그에 저장하지 않는다.
- 기본 화면은 간편 연결 안내이며, 로그인 콘솔은 필요할 때 펼친다. Codex는 같은 패널에서 인증 링크·기기 코드를 제공한다. 로그인 완료·실패·취소와 상태 갱신을 두 CLI에 공통 적용한다.
- 코드 제출 성공·잘못된 입력·이전 세션·중복 제출·취소·연결 끊김을 검증한다. 전체 테스트·린트·타입 검사·Docker 빌드와 화면 확인을 수행한다.

## 결과

- 전체 테스트 23개 파일·287개, 린트, 타입 검사, Docker 이미지 빌드 및 Compose 설정 검증 통과.
- 가짜 CLI로 개행 없는 출력, 코드 전달과 입력 종료, 잘못된 형식·이전 세션·중복 제출 거부, 취소·연결 끊김, 두 CLI의 상태 갱신을 확인했다. 이전 제출 응답이 새 연결 입력을 닫지 않는 UI 회귀 테스트도 통과했다.
- 브라우저에서 Claude의 마스킹 입력과 Enter 제출, Codex의 인증 링크·기기 코드, 기본으로 접힌 콘솔을 확인했다. 데스크톱과 모바일 화면에 가로 넘침이 없었다.
- 인증 볼륨 없는 별도 Docker 컨테이너에서 실제 Claude CLI의 인증 안내를 수신했다. 불완전한 코드의 400 응답, 취소 후 SSE 종료, 이전 세션의 409 응답과 미로그인 상태를 확인했다. 실제 계정 인증 완료 및 모델 실행은 이번 검증에 포함하지 않았다.
- 별도 코드 리뷰에서 필수 수정 사항은 없었다. 새 의존성이나 범용 셸은 추가하지 않았다.
