# 005 로그인 콘솔 입력

> 상태: 완료

## 이유와 범위

출력만 제공하던 로그인 콘솔에 입력 경로가 없어 터미널처럼 조작할 수 없었다. Claude·Codex의 실행 중 로그인 명령에 한 줄씩 입력을 전달하고 Enter 제출·Ctrl+C 취소를 제공한다. 기존 간편 연결과 Claude 전용 인증 코드 제출을 유지한다. 범용 셸이나 새 의존성은 추가하지 않는다.

Codex 기기 코드 로그인은 ChatGPT 보안 설정에서 활성화해야 한다. 해당 설정 안내와 링크를 표시하며 기기 코드 입력 위치는 OpenAI 인증 페이지임을 명확히 한다. 앱은 계정 설정을 대신 변경하지 않는다.

## 검증 기준

- 두 CLI의 콘솔 입력이 현재 세션 stdin에 전달되고 다음 입력을 받을 수 있다.
- 종료·취소·이전 세션과 여러 줄·제어 문자 입력은 거부한다. 기존 Claude 간편 코드 제출 검증을 유지한다.
- 브라우저에서 콘솔 입력·Enter·Ctrl+C와 모바일 배치를 확인한다.
- 테스트·린트·타입 검사·Docker 빌드 후 실행 서비스에 반영한다.

## 결과

- 테스트 23개 파일·293개, 린트, 타입 검사, Docker 빌드 통과. 별도 코드 리뷰에서 수정 사항 없음.
- 가짜 CLI로 두 CLI의 stdin 전달·반복 입력·빈 Enter·이전 세션 거부와 취소·종료 후 입력 거부를 확인했다. 기존 Claude 간편 코드 제출의 일회성·EOF 검증도 유지했다.
- 브라우저에서 Claude 콘솔의 잘못된 입력 후 재입력, Codex 콘솔의 빈 Enter, Ctrl+C 취소, 설정 안내를 확인했다. 데스크톱·모바일에서 가로 넘침이 없었다.
- 인증 볼륨 없는 별도 Docker 컨테이너의 실제 Claude CLI가 두 번의 콘솔 입력을 받고 계속 입력을 기다리는 것을 확인했다. 취소 후 SSE 종료와 이전 세션 입력 409도 확인했다. 계정 인증 완료는 수행하지 않았다.
- Codex의 기기 코드 설정과 브라우저 입력 위치는 [OpenAI 공식 문서](https://learn.chatgpt.com/docs/auth#preferred-device-code-authentication-beta)로 확인했다. Codex stdin 전달 확인은 가짜 CLI 검증이며, 공식 명령의 기기 코드 인증은 브라우저에서 진행한다.
- 범용 셸·전체 화면 터미널 에뮬레이터·새 의존성은 추가하지 않았다.
