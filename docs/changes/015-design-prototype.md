# 015 디자인 문서와 기준 화면

> 상태: 구현·자동 검증 완료 (2026-11-04). 실제 에이전트(Claude·Codex)로 생성한 디자인 문서의 품질은 확인하지 않았다.

## 이유

디자인 문서는 사용자가 붙여 넣은 것만 쓰고 만들지 않았다. 색·글꼴 표만으로는 좋은지 판단하기 어렵고, 프로토타입(화면 정의서)은 요구사항을 모두 승인한 뒤에야 만들어 디자인 피드백이 늦다. 화면은 하나씩 따로 생성되므로 공통 기준 없이 먼저 만들면 화면마다 스타일이 갈린다.

## 범위

- 디자인 단계: 단계 목록의 **디자인 › 디자인 문서**. 디자인 문서 편집·생성·저장과 기준 화면 하나를 한 화면에서 함께 다룬다 ([screens.md](../requirements/screens.md#디자인-단계)).
- 디자인 문서 생성(`POST /api/projects/:id/design/generate`). 작업본이 있으면(처음 붙여 넣은 문서 포함) 그 문서를 반영해 토큰 값과 원칙은 그대로 두고 필요한 것만 덧붙인다. 없으면 앞 문서에서 새로 만든다. 서버는 저장하지 않고 사용자가 저장한다.
- 기준 화면: 별도 구조 없이 화면 정의서 패널을 그대로 쓴다. 승인된 다른 화면 하나의 HTML을 다른 화면의 생성 입력에 더한다.
- 화면에서 디자인 문서가 없을 때 입력란 대신 디자인 단계로 가는 버튼을 둔다. 승인된 화면이 없으면 디자인 단계가 먼저 열린다.
- 문서 규칙(`docs/AGENTS.md`)의 `2-DESIGN.md` 설명을 "그대로 사용한다"에서 "넣은 문서의 값·원칙은 바꾸지 않고 필요한 것만 덧붙인다"로 바꿨다. 이 파일은 모든 생성 프롬프트에 들어간다.

## 제외 범위

- `2-DESIGN.md`를 승인·되돌리기가 있는 문서 행으로 올리는 일 (`designMd`가 소스 15개·테스트 22개 파일에 걸려 있다).
- 화면에서 고친 내용을 디자인 문서에 자동으로 되돌려 쓰기, 스타일 갤러리 페이지, 스크립트로 움직이는 프로토타입.
- (이후 변경) 저장소 프로젝트의 디자인 문서와 화면은 이제 허용한다 ([github.md](../requirements/github.md)). 일괄 초안은 여전히 만들지 않는다.

## 작업

1. `RunKind`에 `design` 추가, `designGate`·`designInputDocs`(화면 정의서와 같은 조건·입력을 재사용), 디자인 프롬프트, 화면 프롬프트의 기준 화면 절.
2. 생성 라우트 `design/generate`.
3. `DesignPanel`(기준 화면은 `ScreenPanel`을 끼움), 단계 목록·기본 단계, 화면 패널의 디자인 입력 제거.
4. 문서 반영.

## 검증

- 서버: 프롬프트(새로/반영/피드백/기준 화면), 생성 조건, 라우트의 base 우선·저장 안 함·잠금·오류. 컴포넌트: `DesignPanel`, 단계 목록·기본 단계.
- 브라우저(헤드리스 Chrome, 가짜 CLI): 새로 만들기와 붙여 넣기 먼저 두 흐름, 390px 폭.

## 결과

- 전체 테스트 48개 파일·646개 통과(기본 단계 규칙 수정 전 실행, 이후 `stage.test.ts`와 관련 파일 재실행 통과), 타입 검사·린트·빌드 통과.
- 브라우저에서 확인: 디자인 단계가 먼저 열림, 생성 결과가 저장 전에는 서버 값을 바꾸지 않음, 저장 뒤 기준 화면 생성·미리보기·승인, 승인하면 다음 화면으로 이동, 붙여 넣은 문서가 편집기에 그대로 있고 변경 버리기로 복귀. 개발 중 발견·수정: 기준 화면을 만들면 디자인 단계에서 화면 단계로 튕기던 문제(기본 단계를 "승인된 화면이 없을 때"로 수정).
- 확인하지 않은 것: 실제 에이전트 출력(가짜 CLI는 고정 응답), 실제 에이전트가 기준 문서의 값을 지키는지.
- 환경 참고: 이 호스트의 Node(26)와 `better-sqlite3` 네이티브 빌드(Node 25용)가 맞지 않아 호스트에서 `npm test`의 DB 테스트가 실패한다. 검증은 복제본에서 `better-sqlite3`만 다시 빌드해 실행했다. 호스트 `node_modules`는 건드리지 않았다.
