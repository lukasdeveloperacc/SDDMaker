# 018 impeccable live로 화면 다듬기

> 상태: 구현·자동 검증 완료 (2026-11-04). 실제 브라우저에서 요소를 골라 변형을 만들고 Accept하는 전체 흐름은 확인하지 않았다.

## 이유

주석 모드(선택·그리기·이름으로 고르기)는 요청을 글로 써서 보내고 결과를 기다리는 방식이라, 화면을 보면서 바로 고치기 어렵다. impeccable의 live 모드는 브라우저에서 요소를 골라 동작을 누르면 디자인 기준을 지킨 변형 3개를 그 자리에서 보여 주고 고르게 한다.

## 범위

- 이미지: impeccable 플러그인(`plugin/`, 커밋 고정)을 `/opt/impeccable`에, 엔진 바이너리를 체크섬 검증 후 `/opt/impeccable/engine`에 넣는다 (홈은 볼륨이라 가려진다).
- 서버(`src/server/live.ts`): 작업 폴더 내보내기·변경 판정·가져오기, `impeccable live` 부팅, 에이전트 대기 루프 실행(Claude·Codex), 종료. 컨테이너 안 보조 서버는 127.0.0.1에만 열리므로 앱이 `0.0.0.0:8401`에서 이어 주고 compose가 호스트 `127.0.0.1:8400`에 연결한다.
- API: `GET·POST·DELETE /api/projects/:id/live`, `POST /api/projects/:id/live/import`. 화면 제공: `GET /screens/:file`(열린 세션만).
- 화면: 화면 정의서의 live 패널(열기·새 탭·가져오기·다시 시작·종료).

- 화면 정의서 화면의 주석 도구 막대(선택·그리기·이름으로 고르기·전체 HTML 편집)와 주석 목록을 뺐다.
- 보조 서버 포트는 `LIVE_PORT`(compose 기본 48400)로 고정한다. live.js가 `localhost:<보조 서버 포트>`를 직접 부르므로 호스트 포트와 컨테이너 안 포트가 같아야 한다.

## 제외 범위

- 여러 프로젝트 동시 세션(포트를 세션마다 나눠야 한다), 앱 안 iframe에서 바로 쓰기(미리보기는 스크립트를 막는다), 변형 슬라이더 값의 앱 저장.

## 검증

- 서버 테스트: 내보내기, 주입 무시 변경 판정, 가져오기(되돌리기·건너뛰기 사유), 화면 제공 경로 검사.
- 이미지: 빌드 후 네트워크 없이 엔진이 돌고 `impeccable live`가 부팅되는 것을 확인했다.
- 에이전트: 같은 프롬프트로 `claude -p`를 돌려 스킬을 읽고 `live-poll` 대기에 들어가는 것(`agentPolling: true`)을 확인했다(호스트). Codex는 확인하지 않았다.
- 전체 테스트 54파일·685개, 타입 검사, 린트 통과.
