# 001 MVP

> 상태: 진행 중 — 구현 작업 1(CLI 확인) 대부분 완료, 코드 작업 전

## 변경 이유

앱을 만들 때마다 SDD 문서를 먼저 만들고, 그 문서로 Agentic 개발을 하기 위한 도구가 필요하다. 이미 쓰고 있는 Claude·OpenAI 구독을 API 키 없이 활용한다.

## 결정 기록 (2026-10-19)

- 요구사항은 인터뷰(11라운드)로 확정했다.
- 생성할 문서 세트는 인터뷰에서 정한 4종(PRD · 아키텍처 · 데이터·API · 태스크) 대신 SDDMaker 자신의 [docs 규칙](../AGENTS.md) 구조로 바꿨다. 한 번 쓰고 끝나는 문서가 아니라 MVP 이후에도 같은 규칙으로 갱신되는 문서를 만들기 위해서다.
- 구독 로그인을 앱 화면에서도 시작할 수 있게 했다 (공식 CLI 로그인 명령 실행).
- 화면 정의서(`screens/<화면>.html`)를 MVP에 넣고 docs 규칙에 `screens/`를 추가했다. 텍스트 요구사항만으로는 코딩 에이전트가 화면 배치를 추측하기 때문이다. 수정 방식은 Orca 내장 브라우저처럼 컴포넌트를 고르거나 그림을 그려 주석을 쌓고, 템플릿으로 묶어 보낸다.
- 문서 검토 후 결정:
  - 승인한 문서는 승인 취소 후 다시 고칠 수 있다. 뒤 문서는 그대로 두고 "앞 문서 변경됨"을 표시한다.
  - 디자인 문서가 없으면 [getdesign.md](https://getdesign.md/)에서 골라 붙여 넣는다. 화면 정의서 전까지 필요하다.
  - 그림 주석은 좌표와 겹치는 컴포넌트만 보낸다. 이미지 첨부는 MVP 이후.
  - 인터뷰 도중 건너뛰기, 프로젝트 삭제를 MVP에 넣는다.
  - 구독이 아닌 로그인은 실행을 막고, 자식 프로세스에서 API 키 환경변수를 지운다.
  - 한 프로젝트에서 에이전트 실행은 한 번에 하나만 한다.
  - SDDMaker의 Codex는 앱 전용 `CODEX_HOME`을 써서 사용자 전역 지시문을 막는다. 그래서 Codex 로그인을 SDDMaker에서 한 번 따로 한다.

## 구현 작업

1. **CLI 확인** — 대부분 완료 (2026-10-19). 실행·스트리밍·세션 이어하기·도구 차단·사용자 설정과 전역 지시문 차단·이어하기 턴의 쓰기 차단·표준입력 프롬프트·로그인/미로그인 상태 출력을 확인해 [1-SYSTEM-ARCHITECTURE.md](../1-SYSTEM-ARCHITECTURE.md#외부-연동-에이전트-cli)에 기록했다. 이 과정에서 Codex가 `--ignore-user-config`로도 전역 `~/.codex/AGENTS.md`를 읽는 것을 찾아 `CODEX_HOME` 분리로 정했다. 남은 것: 두 로그인 명령이 터미널 없는 자식 프로세스에서 URL·코드를 어떻게 내는지. 로그인 명령이 터미널 없이 안 되면 [agent-cli.md](../requirements/agent-cli.md#앱에서-로그인)대로 터미널 로그인 안내로 대신한다.
2. Next.js(TypeScript) 프로젝트 생성, `npm run dev`를 `next dev -H 127.0.0.1`로, `Host`/`Origin` 검사, `.env.local`·`SDDMAKER_DATA_DIR` 처리.
3. SQLite 스키마와 DB 모듈 ([3-DATABASE.md](../3-DATABASE.md)).
4. 에이전트 어댑터 2개(실행·상태 확인·로그인), 실행 환경(작업 폴더, Codex 홈, API 키 제거), SSE 공통 처리, 프로젝트당 실행 1개 잠금(`globalThis`) ([requirements/agent-cli.md](../requirements/agent-cli.md)).
5. 프로젝트 API·화면 (디자인 문서 입력과 getdesign.md 안내, 삭제 포함).
6. 인터뷰 API·화면 (재시도, 세션 복구, 도중 건너뛰기, 승인 취소 포함).
7. 문서 API·화면 — 편집기, 피드백, 되돌리기, 승인·승인 취소, 생성 조건 검사, 목록 확정, "앞 문서 변경됨"·"목록에서 빠짐", 출력 울타리 벗기기.
8. 화면 정의서 — iframe 미리보기, 선택·그리기 주석과 주석 목록, 요청 템플릿과 미리보기 API, 응답 블록 반영·정리.
9. 문서 종류별 프롬프트와 화면 주석 템플릿. 문서 규칙은 `docs/AGENTS.md`를 실행 시 읽는다.
10. zip 내보내기.
11. 아래 검증 시나리오 수행 후 문서를 실제 상태로 갱신하고 `예정` 표시를 제거한다. 그때 SDDMaker 자신의 화면 정의서(`docs/screens/`)도 실제 화면 기준으로 추가한다.

## 검증 방법

각 요구사항 문서의 완료·테스트 기준을 모두 통과하고, 아래 시나리오가 처음부터 끝까지 동작해야 한다.

1. `npm run dev`로 실행 후 `127.0.0.1`로 접속 (다른 기기에서는 접속되지 않음)
2. 새 프로젝트 생성, 아이디어 입력, getdesign.md에서 고른 디자인 문서 붙여 넣기
3. Claude로 인터뷰 → 완료 → 요약 수정·승인
4. Codex로 `0-PRODUCT.md` 생성 → 직접 수정 → 피드백 재생성 → 되돌리기 → 다시 재생성 → 승인 → 요구사항 문서 목록 확인
5. 단계마다 에이전트를 바꿔 가며 `1` → `3` → `4`(화면 목록 확인) → 요구사항 문서 전부 승인
6. 화면 정의서 하나에서 컴포넌트 수정 주석 2개 + 그림 주석 1개 + 질문 1개를 쌓고 보내기 전 미리보기 확인 → 한 번에 보내기 → 해당 컴포넌트만 바뀌고 질문 답이 보이는지 확인 → 되돌리기 → 다시 보내고 승인. 나머지 화면도 승인
7. `changes/001-mvp.md` 승인
8. `0-PRODUCT.md` 승인 취소 → 뒤 문서에 "앞 문서 변경됨" 확인 → 링크 하나 추가·하나 삭제 후 다시 승인 → 새 문서 생성, 빠진 문서 삭제
9. zip 다운로드, `docs/` 구조와 `AGENTS.md` · `2-DESIGN.md` · `screens/` 포함 확인
10. 앱 재시작 후 프로젝트·문서·상태 유지 확인
11. 두 CLI를 각각 로그아웃 → 앱의 로그인 버튼으로 구독 로그인 → 상태가 로그인됨으로 바뀌고 생성이 되는지 확인
12. 셸에 `ANTHROPIC_API_KEY`를 둔 채 실행 → 구독으로 실행되는지 확인
13. 별도 프로젝트에서 인터뷰 도중 건너뛰기 → `0-PRODUCT.md` 생성 확인 → 프로젝트 삭제
